## 一、一分钟结论

1. **这场论坛回答的是「智能怎么被交付」，不是「模型有多强」**。主线被官方写成一句话：**创造 Token、成就 Agent、交付生产力**。三层递进——千问 AI 平台供 Token，Agent Studio 把 Token 变成 Agent，Qoder / 千问办公 / 千问 App / 千问硬件把 Agent 变成人能用上的东西。
2. **文征给出了全场最重要的一次口径转换**：不要看「每百万 Token 多少钱」，要看**智能价值密度 = 单任务价值 × Token 生产效率 × 单 Token 能力**。他的类比很硬：电价下降不等于电力产业通缩，电价便宜才让电进入工厂、公司、家庭。
3. **平台侧的四张底牌**：MaaS 客户数一年 **6 倍**、**99.9%** 生产级 SLA、**十亿级**单客户峰值 TPM、**CMaaS 机密推理**（数据可用不可见）。弹性上，模型冷启动从 **1200 秒压到 70 秒**，一分钟可拉起 **1 万个 Pod**，首 Token 延迟降 **38%**，Prompt Caching 成本最高省 **95%**。
4. **Agent Studio 是这次真正的「新产品」**：企业级全栈 Agent 服务平台，按任务自动路由模型、24 小时托管、内置自进化引擎（运行观测 → AI 评测器 → AI 优化器 → 自动验证）。配套 **50+ 原子 API** 与「一次请求搞定」的 Agent API。
5. **应用层三件事同时发生**：Qoder 从 IDE 变成**任务优先的 Agentic Coding Platform**（非专业开发者已占 30%、非编程任务超 50%、80% 代码由智能体写）；千问办公押注 **Enterprise Context**（企业上下文）；Qwen Intelligence 把手机智能做成可交付方案，**不做硬件**。
6. **一个反直觉的数字**：千问 Personal Agent 已有 **3 亿用户**接入，且**超 60%** 的用户在处理理财、健康、生活等复杂需求后会**转向工作助理**——生活场景是工作场景的入口，不是相反。

## 四、逐场精读

### 4.1 文征（集团战略副总裁、ATH 事业群 MaaS 业务线总裁）《千问 AI 平台，让智能投入生产》（03:44–27:52）

#### 开场：三个圆圈，把「我们在哪」画清楚

他用三个同心圆回答「AGI 到了没有」这个吵不出结果的问题：

| 圆圈 | 含义 | 判断 |
|---|---|---|
| 第一圈（已到达） | 多少人在用 AI、用得多深、基础设施是否完善 | 三者都还在早期，且在快速增长，所以这个圈**很小** |
| 第二圈（可想象的天花板） | 把现有场景与产业中「有智能判断、智能驱动、执行」的部分全交给 AI：写代码、个人助理、视频创作、数字员工、具身智能 | 比第一圈大很多，是**了不起的里程碑**，但它在解决**已知问题**，边界仍在 |
| 第三圈（尚未命名的空间） | AI 24 小时不间断思考、自我进化后，去挑战人类**现在无法想象、无法预料**的难题 | 打开了新的交互方式、驱动方式和新市场，**可能远超前两个圈** |

结论只有一句：**AGI 之路刚刚开始**。他补了一条历史规律——通用技术越过某个临界点后，会从「技术革命」变成「社会基础设施」，电力电气革命如此，互联网革命如此，机器智能革命也如此。

#### 核心论证：从「单价」转向「价值密度」

先立事实：过去三年日均 Token 量是一条**非常明确的指数曲线**。所以「AI 需求有多大、增速多少」已经不需要再证明，**真正的问题是——谁能把智能变成最后交付的结果**。

再破一个流行判断。有人说模型越来越便宜，所以 AI 在通缩。他的回应分两层：

- 前半句对：单价确实在降；
- 后半句错：**电价下降不代表电力产业通缩**。电价更便宜、更稳定，才让电力广泛进入工厂、公司、家庭，基于电的**上层市场反而更繁荣**。

于是提出**智能价值密度**：

> 智能价值密度 = **单任务价值** × **Token 生产效率** × **单 Token 能力**

| 因子 | 含义 | 观察点 |
|---|---|---|
| 单任务价值 | 一个任务能完成的智能上限是否明显提升 | 我们究竟多愿意把**核心、关键、复杂**的问题交给 AI——从一次简单对话，到一份深度报告、一次靶向药筛选、一套芯片电路设计 |
| Token 生产效率 | 单位时间能生成多少 Token | 不能只看速度，还要看**并发稳定性**：高峰期任务不排队、复杂任务不超时 |
| 单 Token 能力 | 同样数量的 Token 现在能做多难的事 | 同样任务未来可用**更少 Token** 完成 |

三者相乘，就是**单位时间内 AI 输出智能的上限**。

#### 阿里的下注：五层各司其职

| 层 | 负责什么 | 判断句 |
|---|---|---|
| 芯片与基础设施 | 锚定**算力供给** | 以阿里云为主 |
| 千问大模型 | 持续提升**智能上限** | — |
| 模型服务 | 让智能**运行更高效、覆盖更广** | — |
| Agent 服务 | 把 **Token 转化成生产力** | 他明确说这是后面要着重加强的部分 |
| AI 原生应用 | 让每个人和客户**低门槛用上智能** | — |

配套数字：**到 2032 年，阿里运营的算力规模将超过 20GW**；过去不到一年，阿里云 MaaS 平台服务客户数**增长到 6 倍**，平台 ARR 近期**突破 200 亿元人民币**（绝对值口径待核，6 倍增长与公开报道一致）。

#### 模型服务竞争力的四个支点

1. **模型本身**——「好的模型自己就是代言人」。要全模态、全尺寸、一流，且新模型上线要**第一时间可用**；
2. **推理效率**——好模型还要跑得快、跑得省；
3. **企业级稳定与安全**——平台值得被信赖；
4. **灵活的服务模式**——不同预算、不同团队要匹配不同的服务与算力。

#### 模型生态：自研 + 开源双线

**自研通用模型**：从 2025 年 9 月的 Qwen3-Max 到 Qwen3.8-Max，一年内多次迭代。9 月 2 日 Qwen3.8-Max 完成一次**自进化升级**，在 AA 智能指数榜单位列**国内模型榜首**。新架构 **Qwen3.8-Flash-Next** 只激活 **6B** 参数，价格大幅降低、效率大幅上升而智能未降，AA 智能指数比 3.7 的 Plus 还高 **15 分**。

**全模态全尺寸**：图像、视频、音频、音乐、世界模型全部自研，尺寸从端侧轻量到云端旗舰全覆盖，理解与生成兼备。本次发布 **4 个多模态模型**：

| 模型 | 定位 |
|---|---|
| Qwen-Image 3.1 | 图像 |
| HappyOyster 2.0 Preview | 世界模型 |
| HappyShrimp 1.1 | 音乐（新面孔） |
| Qwen-Audio-Realtime 3.1 | 实时语音 |

同时原 Qwen-Audio 的识别与合成模型同步升级；下一代视频模型 **HappyHorse** 很快见面。开源侧，Qwen3.8-27B 开源约两个月即成为 **Hugging Face 历史上点赞最多的模型**。

**开放生态**：原则是「全球一流的开源模型第一时间接入」——DeepSeek、Kimi、GLM 开源后第一时间上线千问 AI 平台。

#### 弹性：应对「开机风暴」

他给了一个非常具体的场景：大客户每天早上 9 点上班，员工陆续到岗，销售团队让 Agent 写拜访材料，研发打开编程 Agent 跑代码——短时间内涌入海量调用，他们内部管这叫**开机风暴**。

对策是自研 **FlashBoot** 做到**秒级启动**，配合 **UniScheduler** 智能调度让算力瞬间扩容：**以前需要小时级调度的任务，现在以极快速度完成启动调度**。对外口径是模型弹性启动时间由 **1200 秒降到 70 秒**、**一分钟可拉起 1 万个 Pod**、首 Token 延迟降低 **38%**、Prompt Caching 成本最高节省 **95%**（这几个数字来自官方通稿，与现场表述一致）。底层是**大规模分布式异构算力集群**，用自研推理能力屏蔽芯片与架构差异。

#### 企业级三承诺：可保障、可信任、可治理

| 承诺 | 内容 |
|---|---|
| **可保障** | **99.9%** 生产级 SLA；单客户峰值 **十亿级 TPM** |
| **可信任** | **CMaaS 机密推理**：数据可用不可见，数据主权归客户，全链路加密与审计，敏感数据不泄露 |
| **可治理** | 秒级监控告警；精细化成本治理；每次调用**有据可查、可控可管** |

他的原话逻辑是：做到这三项，**「企业级」才算是对客户兑现的承诺**，而不只是营销词。

#### 四档服务模式：按客户真实场景切

| 客户 | 诉求 | 对应方案 |
|---|---|---|
| 个人开发者、学生 | 「我想写代码，能不能先试试」 | **Token Plan 个人版**，免费额度起步，0 门槛 |
| 日常用 AI 的团队 | 比 API 按量付费更有性价比；按坐席分配、团队管理 | **Token Plan 团队版**，两者兼得 |
| 把 AI 嵌进产品的企业 | 对延迟敏感 / 高峰期要确定性保障 | **优速模式**（TPS 最高 2 倍）/ **吞吐预留服务** |
| 大型金融政企 | 资源独享、定制部署 | **DTU 专属资源** + 定制模型 |

**Token Plan** 是这部分的重点：一份订阅覆盖多模型（Qwen、Kimi、GLM、DeepSeek 等），不用为每个模型单独开通；**Harness 工程能力也纳入订阅**，每月赠送免费额度且**独立计量、不占订阅 credits**；还能在阿里系 AI 产品间共享折扣（目前千问 App 与 Qoder 个人版已支持，千问办公 10 月支持）。

#### Agent Studio：把整条 Harness 链路沉淀成产品

他先讲清 Agent 运转的底层链路：**模型服务做复杂推理、吐出 Token → 链路做决策规划、运行执行、持续优化 → 链路把业务上下文送回模型**。环环相扣：上下文越准，规划越可靠；运行越稳，工具调用结果越可用；结果可用，优化和进化才有依据。

所以「运维、系统对接、自我优化」**不该是散落各处的零散功能**，它们是这条链路上不可缺少的一环。但让每家企业自己开发、自己优化，「很重也很慢」。

于是发布 **Agent Studio**——企业级全栈 Agent 服务平台：

- Harness 框架与模型**深度匹配**，按任务**自动路由模型**，做到成本更低、效果更好；
- 所有任务**24 小时不间断托管运行**；
- 提供丰富的上下文连接能力：企业内部知识库、外部软件**无缝接入**。

**两种开发姿势**（同一运行底座）：

| 姿势 | 面向 | 手段 |
|---|---|---|
| 完全自主掌控 | 要把 Agent 深嵌进自己系统的团队 | **50+ 原子 API**：创建运行环境、连接长期记忆、搜索、工具服务、发起会话、部署——像搭积木一样自由组合 |
| 业务为先 | 想先让业务跑起来、快速验证的团队 | 即将推出**全新 Agent API**：环境、记忆、工具部署原本要逐项调用配置，现在**一次请求全部搞定** |

#### 自进化引擎：四个组件一个闭环

| 组件 | 作用 |
|---|---|
| **运行观测** | 积累上下文：对话、日志、知识 |
| **AI 评测器** | 自动复盘、轨迹回放，发现共性问题 |
| **AI 优化器** | 按复盘结论给方案：调 prompt、调参数配置，必要时**优化对应模型** |
| **自动验证** | 小流量先验证，有效再扩到全量生产流量 |

他的收束很关键：**每转一圈，Agent 应该更懂业务一点**，这些沉淀下来的经验就是企业积累的 **AI 资产**。

#### One Key MCP：一个 API Key 连接 100+ 服务

Agent 能办多大事，不只取决于模型与工程，还取决于**能不能调用真实世界的服务**——查机票、看路况、审合同、认发票。这些背后是行业多年积累的专业经验与功能。

他举了个真实请求作演示：「每天监测飞往杭州的机票价格，结合交通信息生成黄金周旅游热度地图，不限服务站点，保持小时更新。」过去开发者要为每个工具分别注册账号、鉴权，流程繁琐；现在平台自己完成**理解需求 → 寻找工具 → 发起调用**（机票找飞猪、路况找高德），**鉴权自动完成**。开发者只需要做一件事：**把问题定义清楚**。

### 4.2 丁宇（ATH 事业群副总裁、Qoder 产品线总裁）《全新 Qoder：不止编程，无限创造》（54:38–75:25）

#### 三个趋势，把「AI Coding」重新定义

Qoder 去年 8 月上线，一年服务全球**超 800 万开发者**。他从用户行为里读出三个变化：

1. **更简约的交互形态**：服务专业开发者时仍能看到 Git、Worktree、Computer Use、Browser Use、Verify 这些专业工具；处理通用任务时则收起来，只留一个更简约的页面，带来**极致专注的心流体验**；

3. **更强大的 Harness**：多模型适配，且 Qoder 与 Qwen **联合设计、联合优化**，把 Qwen 的能力发挥到极致。

#### 升级一：能力边界持续延伸

| 变化 | 从 | 到 |
|---|---|---|
| 产品中心 | **代码优先 / 代码为中心**（AI IDE） | **任务优先 / 任务为中心** |
| 人的动作 | 审查、检查、验证代码 | **计划任务、委派任务、确认结果** |
| 覆盖面 | 设计 → 开发 → 测试 | **计划 → 设计 → 实现 → 测试 → 维护 → 发布**（软件全生命周期） |

注意力的上移直接换来吞吐：人能并发管理更多任务，并发度与吞吐量上升，效率自然提升。他给了一个体感极强的例子：**在手机上开发一款移动 App，从提出想法到部署到这台手机上，不到一小时**。

#### 升级二：协作方式——让讨论发生在任务现场

他先描述旧方式的问题：人在会议室或 IM 里讨论，形成结论后委托一个人整理出来再交给模型/智能体。代价是**注意力分散、上下文分散、产物碎片化**。

对策是两个新功能：

| 功能 | 作用 |
|---|---|
| **Project** | 围绕一个大目标拆解成具体事项，跟进每个事项的进度与阶段 |
| **Discussion** | 每个事项可展开讨论，把人、智能体都拉进一个群组，讨论完形成结论交给智能体执行，人再确认结果 |

一句话概括价值：**让讨论发生在任务的现场**，与模型共享上下文，讨论历史和资产都挂在任务上——**人不用再做智能体的搬运工**。

#### 升级三：与用户共同成长（三层能力）

| 层 | 内容 |
|---|---|
| **能力可扩展** | **150+ 连接器、70+ 插件、2 万+ 精选技能**——想做的事几乎都能找到现成技能，不用从 0 搭建 |

#### Code Security：把安全从「规则扫描」换成「模型内生」

前提判断很硬：用 AI Coding 后代码量会爆发，**代码安全成为新挑战**。而旧范式是**基于规则和正则表达式扫描**——本质是把存量知识经验写成规则，扫出问题再让人修。

新范式的逻辑是：**代码既然都是 AI 生成的，它也能检查代码安全性**——只要把先验知识能力 build 进模型。于是他基于自研大语言模型构建了**从推理、自发现到自解决修复的主动安全闭环**，做到「**生成即审查，审查即修复**」。

为什么节点要前移：以前安全扫描在「提交仓库 / 发布之前」，那时研发工作已完成，倒回去改代价最大。今天 AI Coding 在每个阶段都在生成代码、变更需求、提交代码，所以**每个切面都可以 fix**——他们做了**四层切面**：编码时、变更时、提交前、全仓扫描。

| 指标 | 数值 |
|---|---|
| 问题识别准确率 | **90%**（比传统方式近乎翻倍） |
| 漏洞检出率 | **83%** |
| 上线两个月累计扫描 | **180 万次** |
| 发现并修复漏洞 | **5.8 万个** |
| 企业管理 | 成员**零配置**，管理员开通即可用 |

### 4.3 陈宇森（千问办公 CEO）《千问办公：Context Is All You Need》（75:56–100:22）

#### 命题：模型有智能，Agent 没有「企业」

他先给了一个非常诚实的前提：这个舞台上站着中国最强的模型引擎之一，百炼提供的推理量可能是国内最大。但——

> 模型能力距离企业生产力还有哪些差距？有了强大的模型之后，怎么把它落地在企业里？

他列了三个现实困难：

| 困难 | 具体表现 |
|---|---|
| **懂很多事，但不懂企业** | 问「我们公司华东区今年毛利是多少」，任何 Agent 都答不出来——它不知道你公司是谁、数据在哪、毛利率怎么算、原始数据来自哪些系统 |
| **优秀个体无法复制** | 组织里有人用 AI 一周的活一天干完，但经验没分享出去，其他人还在用传统方式或用得不熟练 |
| **数据安全** | 有安全研究员买了「中转站」的数据，发现大量企业内部敏感信息、账号密钥泄露 |

结论：如果一个企业级 Agent **不懂业务、不能协同、不保障数据安全**，那就用不起来。

而三者之上有一个共同前提——**数据**。他的论断是：**企业级 Agent 真正落地的前提是数据**。

#### 解法：Enterprise Context（企业上下文）

要把企业过去积累的数据**全部连接**到一个平台，对大量**非结构化数据**做**理解与压缩**，最后变成**可复用的企业上下文知识**。

产品目标三个词：**懂业务、能协同、信得过**。

| 目标 | 具体含义 |
|---|---|
| **懂业务** | 能拿到企业过往**压缩后的有效数据**：知道公司代表什么、华东区是哪几个省、毛利率怎么算、数据来自哪些系统 |
| **能协同** | 一个优秀员工的经验能快速分享给整个组织，让大家把 AI 用到 95 分甚至 100 分，而不是有人 80 分、有人 20 分 |
| **信得过** | Agent 的**操作边界清晰、操作可控**；敏感数据不该被 AI 访问，产物中若含敏感信息应被管控，**不出企业数据边界** |

#### 古茗的案例：最能说明「上下文」价值的一组对照

古茗是茶饮/餐饮净利润前十、总部在杭州、**1 万多家门店**的企业。新品上市后要教每个店员做饮品，过去店员忘了某个步骤得问店长、问同事。

他给了一组非常有说服力的对照：

| 右边这些问题（任何 Chatbot 都能答） | 左边这些问题（只有懂企业的 Agent 能答） |
|---|---|
| 中国新茶饮市场有多大？ | 古茗华东区制冰机的滤芯多久更换？ |
| 去年 Top3 销量的茶饮是哪三款？ | 古茗「芭乐冰奶茶」的茶汤要放多少毫升？ |
| 2025 年全国茶饮消费人群画像？ | 古茗的泡茶机开不了机该怎么处理？ |

差距不在模型智能，而在**这些信息只存在于企业内部**：每个物品代表什么、对应说明书与使用规范、每款茶饮的 SOP 每一步。

#### 技术判断：为什么必须「压缩」

他给了一个硬约束：据钉钉数据统计，中国中大型企业平均数据量有 **150 PB**；而当前最好的模型上下文窗口最大只有 **100 万 token**。

100 万 token 意味着什么？**大约丢一个 50 兆以上的文件进去，如果不做压缩、要全文直接理解，上下文窗口就会爆掉**。

所以这个产品的关键词是「**有效且有限**」——有效：拿出当前任务真正需要的信息；有限：不能打爆模型上下文。

他拿 Palantir 做了类比：Palantir 靠大量工程师在客户现场理解业务，把业务梳理成「本体（Ontology）」架构——所有实体是什么、实体之间关系是什么。而今天大模型可以把过去难以整理的非结构化数据有效整理出来，做成类似**渐进式暴露**的目录结构：

- 公司有哪些人、每人属性、当前负责什么任务、擅长什么不擅长什么；
- 当前有哪些项目在进展、参与的人有谁、开过几次会、每次会议核心内容；
- 当前还有哪些待办。

同时对**实体之间的关联关系**做分析。这样才得到一个既有企业全部信息、又压缩到可被 Agent 使用的产品。

#### 模型底座：多模态理解 + 联合压缩模型

- **Qwen3.8-Omni-Flash** 负责理解企业沉寂多年的多模态数据：把奶茶制作教程统一理解、实现文本可检索，甚至把长视频转成漫画，让店员一眼扫到关键信息；

#### 数字员工：三个前提 + 一个「真 AI 不录音」

数字员工本质是**业务场景**。要真正进企业办事，需要三个前提：

1. **托管能力**：千问办公提供 manage agent 能力，自定义 Agent 可方便跑起来，基建部分被 cover——你只需定义业务场景、system prompt、要连哪些数据；

3. **组织身份**（钉钉提供）：不是像过去一个 Bot 进去就行，而要**归属于某个部门、拿到该部门的数据权限、有企业内联系方式、有工号**——像人类员工一样管理，才能在负责任的前提下解决业务问题。

这里他给了一个我认为全场最好的产品洞察：

> **真 AI 不录音。** 我们对「旁边有同事打字记东西」不敏感，但「有人想把你的语音全录下来」会不适。ASR 准确率已经高到**不需要留存录音**——所以这不是录音类产品，是**会议笔记类产品**。

承接这个判断的底气来自前作：**钉钉 A1** 已拿到国内卡片式 AI 录音笔全品类全网销量第一，出货**大几十万台、接近 100 万台**。

流程因此被压到当天完成：记录现场对话 → 信息回公司 → 销售不用写 CRM → 好灵感自动发现并同步给其他同事。

#### 安全：执行有边界 + 数据边界

| 维度 | 做法 |
|---|---|
| **执行有边界** | 每个操作被记录；大量操作在**沙箱**内进行；文件删除类操作**提前备份**，误删可找回。他引了今年 2 月「小龙虾（OpenClaw）」火热时 Meta 安全主管邮件被删光的例子 |

### 4.4 郑嗣寿（ATH 事业群千问事业部副总裁、千问产品总经理）《千问，让智能服务每一个人》（100:31–116:28）

#### 三个观察，把「Personal Agent」的必要性讲清楚

千问去年 11 月上线，第一天就提「打造属于每一个人的 AI 助理，让智能平等地服务每个人」。今天**超 3 亿人**在用千问。

十个月迭代下来，他给出三个观察：

| 观察 | 数字 | 解读 |
|---|---|---|
| 复杂任务暴涨 | 过去几个月**翻了 5 倍**（比例，非总量） | **越复杂的问题越需要更强的智能** |
| 对话轮次变深 | 平均**5–8 轮**，仍在高速增长 | 不是用户没讲清楚，而是沟通本身就是**越来越打开、越来越深入细节**的过程，需要充分智能去对齐内在目的与真实意图 |

#### 产品形态：从 Chatbot 到 Personal Agent

随着 Qwen3.8 在 Agentic 能力上的突破，加上 App / PC / 眼镜 / OS 的多端持续交互，长期愿景第一次有了清晰的产品形态：**把千问打造成属于你个人的 Personal Agent**——记录你、理解你、服务你。

模型分工说得很清楚：

- **Qwen3.8-Max** 让千问真正具备提供**高复杂度 Agentic 服务**的能力，是大规模高质量交付的基础；
- **Qwen3.8-Flash** 在效果与成本之间平衡得好，对大众用户非常关键——**大众用户对 Token 更敏感**；
- 此外几乎用了阿里所有模型：HappyHorse、Omni、Audio 等。

他还专门感谢了 MaaS 团队：功能从 Chat 到语音、Live 长程任务、视频创作、AI 硬件，不同场景对底层需求完全不同——**实时交互要求极快，长程任务要求很稳，通用对话要求极高并发**，这需要 MaaS 平台在模型部署、服务调度、运行保障上紧密配合。

#### 核心方法论：单一场景的上下文做不好单一场景

这是他这场最值得记的一句判断：

> 如果只有你单一场景的 Context，其实很难彻底做好这个单一场景。因为你的健康不光是跟生不生病有关，跟运动、饮食、作息规律都相关；你小孩的教育规划会影响一个家庭的资产配置和抗风险能力。

所以要理解一个人，必须构建**围绕这个人的全域、终身的 Context**。三层：

| 层 | 内容 |
|---|---|
| **通用 Context（围绕身份）** | 职业身份、所处阶段、时间场景都在持续变化——过去是学生今天是员工，过去是小孩今天已是父母。要在动态中持续提炼身份 Context、沉淀特性 |
| **领域级 Context** | 理财、学习、工作等，既要有垂直 Context，也要能跨场景灵活调用 |
| **多终端 Context** | 新终端（尤其具身 AI）带来高价值的、带环境感知的 Context。如千问 AI 眼镜新版本能通过**虹膜识别**了解身体更多健康信号 |

他还给了一个终局判断：你的 Agent 不会只单向执行任务，而会逐渐形成一种特殊能力——**理解你的长期目标、理解你内在的性格、识别你当下表达与真实利益之间的偏差，甚至在关键处提醒你「这件事做得不太对」**。

#### 四个场景：健康、学习、工作、生活

**健康**（需求占比**超 20%**，稳定增长）

难点在「记忆归属」：用户咨询症状时若不明确指向，你不知道他问的是自己、小孩还是家长（家长有很多位）。他们构建了**9 类人群的记忆结构**区分不同对象画像——「你和你家里人的情况不能混」。

三层建设：健康 Memory 系统（含多层隐私调用机制）+ 持续引入外部数据（穿戴设备、手机数据：运动、睡眠、血氧）+ 多年积累的医疗模型 → 共同构成线上运行的**医疗 Agent**。

**学习**（**80%** 用户提过学习问题，高频用户每天用；AI 学习服务单日请求峰值**超 1 亿次**）

把长期积累的题库解题能力变成 **Skill** 交给 Agent 作为原子能力，加上不断积累的对学生的理解构建**个性化学习档案**。案例：作业批改不只给答案，还提示知识点薄弱点（「这个点最近已经错了好几次」），再针对薄弱点给练习题。

路径：主动学习助手（已在加速实现）→ 启发式学习（探索中）→ Learning for life（终身学习）。

**工作**（定义被放宽了）

他对「工作」的定义值得注意：**远不止在公司的事**——带回家的工作、家庭资产配置、职业规划、小孩日常安排、自己的兴趣爱好，都需要专业支持。

关键数字：学习和健康用户在咨询复杂问题后，**60% 的后续动作会转移到工作助理**继续展开。所以千问的工作助理更像一个**能深入分析、交付专业成果的综合研究平台**。

工程上最实在的一条：在推理强度与速度的调度机制上下功夫，把算力集中在**更关键的环节**（容易出错的地方、最难的地方），**效果不变的情况下每个用户 Token 消耗降低 40%**。此外以个人账号与 Skill 建设专属 AI Workspace（含网盘数据）；交付物迭代策略分两类——给他人的保持专业性，留给自己的用更长上下文换更强个性化。

**生活**（初心）

AI 购物出行、兴趣视频生成、高考志愿 Agent。方法上：通过事件、场景、时间等信息把握每个人最关键的 **state 变化**，把 state 变成长期的、连续更新的个人 Context。

### 4.6 许主洪（ATH 事业群副总裁、Token Foundry Qwen 手机智能负责人）《Qwen Intelligence：让个人智能走进真实世界》（128:30–149:57）

#### 判断：Agent Phone 是个人 ASI 的必经之路

他的两个前提数字很关键：**手机占据大部分人 90% 的使用时长**，**用户 90% 的上下文沉淀在手机上**。所以——

他对现状的诊断也不客气：当前手机助手的 DAU 和付费率都比较低，**本质原因是智能化程度不够**。而随着智能化提升，AI 手机与手机助手的市场空间非常广阔——使用时长、交互频次、任务深度、付费意愿都将爆发式增长。

|---|---|---|

终局一句话：Agent 手机不仅是能办事的助手，也会是**可持续进化、最懂你的个人伙伴**。

#### 定位：ToB，不做手机硬件

**Qwen Intelligence 当日正式开启公测**，定位是面向下一代 AI 手机智能的 **ToB 产品与解决方案**，明确「**我们不自只做手机硬件**」（不做硬件）。三层价值：

| 层 | 提供什么 |
|---|---|
| 底层（模型） | 基于千问大模型、**专为手机场景深度定制**的智能底座——手机场景能力更强，性价比也更高 |

| 上层（方案） | 高价值垂直场景解决方案 |

#### 三个 SOTA 级 Agent

**① MobilePlannerAgent（手机的大脑）**——解决智能规划

职责：用户意图理解、复杂任务拆解、工具编排调用。能力要求：精准理解、长程规划、动态调整。例：「帮我安排周末去趟上海出差」要能自主拆成订机票、订酒店、设日程、规划路线等子任务，并根据变化动态调整。

四个核心挑战：模糊指令可视化、跨多轮信息丢失；工具/Skill 调用冲突；长程任务中途出错与异常处理；如何用好过往「质疑」让 AI 越用越懂你。

两大解法：

1. **模型与 Harness 在真实环境交互中协同演进**——模型通过智能体强化学习负责理解/规划/决策，Harness 负责管理状态、记忆、技能，两者靠**真实环境执行反馈**不断迭代。**模型和 Harness 一起进化，Agent 的能力上限才能持续被推高**；
2. **双层记忆**——工作记忆随任务演进；长期记忆把短期经验沉淀为长期认知与用户偏好。每次交互记忆进入编排中枢，经筛选召回后按需接入任务上下文。

评测：手机行业模型在手机开放评测集取得 **SOTA**，**比参数更大的通用模型效果更好**，同时通用能力保持第一梯队；真实业务场景任务成功率**超 90%**。

**② Mobile-UseAgent（手机的操作）**——解决智能执行

现实约束：手机生态不统一，部分 App 有 API，更多仍需 GUI；而用户真实任务往往跨多个 App。

四要求：App 覆盖广、执行稳、效率高、安全隐私有保障。

策略：**API 优先，GUI 兜底**——有接口时通过 MCP、API、COI、Deeplink 等方式直接调用缩短路径；没接口时用视觉理解 + GUI 操作覆盖长尾；模型按任务目标与实时状态**动态组合**两种方式。再叠加端云协同推理、安全护栏。

安全边界三条，说得非常明确：**危险操作坚决不做；敏感操作不擅自决定；需要用户确认的有风险关键决策始终交给用户接管**。

评测：6 项主流手机执行评测均取得 SOTA；真机端到端实测整体任务成功率 **90%**；对比行业头部方案，**单步时延降低 16%、平均任务步数减少 3.4 步、安全评分高出 23 个百分点**。

**③ MobileCreativeAgent（影像创作）**——解决「一句话出成品」

手机影像的约束很苛刻：效果好、速度快、成本低、听得懂口语化要求，还要处理人像（P 图要自然）、壁纸（兼顾真实感与画面适配）。

| 侧 | 做法 |
|---|---|
| 模型侧 | **6B 轻量模型**，通过**步数蒸馏 + 强化学习**把生成过程从 **100 步压缩到 8 步**，兼顾效率、画质、指令遵循；结合高质量影像数据与多分辨率训练 |
| Agent 侧 | **27B 规划模型**理解需求、编排任务，把口语化需求转成清晰指令，通过任务拆解、多步编辑、参考图自动调用工具完成创作 |

效果：手机影像专场景行业领先（人像表情、背景虚化、目标消除、手机壁纸等对比头部竞品有明显优势）；**首图生成仅需 3 秒，比竞品提速 2 倍**，综合性价比提升 2–3 倍。

#### 荣耀的落地数字

与荣耀紧密合作打造垂域模型与手机 Agent 方案，整体效果行业领先：

| 指标 | 数值 |
|---|---|
| 综合任务准确率 | **91.8%** |
| GUI 操作速度 | **3.6 秒** |
| 复杂长程任务 | 操作步数 **100+** |
| 端到端服务闭环率 | **90%** |

他强调这些数字「经过实践打磨、已真实落地、能跑出来」。

#### 生态：先开放评测

Agent Phone 仍处早期，他选择从**开放评测体系**入手，**开放 4 套基准评测集**，覆盖「从规划到执行、从云端到真机、从能力到安全」，构成可量化、可复现、可对比的行业标准。

一句话点题：**开放这些评测不是证明谁比谁更强，而是希望它成为行业共同的基础设施**。

### 4.7 对话《模型进产业，跑通的路和踩过的坑》（150:28–197:27）

主持人是**徐栋**（MaaS 业务线千问大模型业务副总裁）。他开场就把自己的两个 KPI 说出来了，这也是全场最诚实的一句主持词：

> 我关心两件事：第一，大模型技术以多快的速度奔跑、边界往哪里推移；第二，**哪些应用真的规模化发展起来了，哪些企业真的因为大模型挣到钱了**。

他还给了一个时代判断：**今年已经不再探讨「接入模型」这件事，而是探讨怎么进入业务、在业务中怎么落地**。

#### 陈炯（贝壳集团 CTO）：把个性化开发权交给城市

**跑通的部分**：过去贝壳有很多城市个性化需求做不了，只能做通用需求。现在在 AI 应用开发平台上对接内部数据接口与业务系统接口，**各城市职能可以自主开发应用**——海报、房源物料、客户需求洞察、客户咨询回复等。目前**每周约 1 万多名内部员工在用**，累计沉淀**约 12000 多个 Skill**。

**还在攻坚的部分**：管理、辅导、培训场景，他们称之为「管理分身」或「AI 陪练」。目标是让管理者不只是盯指标，而是以**赋能者**角色跟商圈经理、经纪人复盘「哪里可以做得更好」。难点在于：要懂业务上下文、懂行业经验，还要**把多次辅导串起来**。

第二轮追问「坎在哪」时，他讲了贝壳最特殊的一点：**线上线下一体且线下更重**。买房过程中客户与经纪人的真实需求、业主底价，过去只存在**经纪人脑子里**。而这类「高额低频」交易对信息准确与决策准确极度在意，所以**数据闭环是第一位**。难点是录音的阻力——客户同不同意、经纪人愿不愿意。他们的解法是让录音**立刻产生回报**：直接生成带看报告、房源物料，让经纪人先尝到甜头，数据才沉淀得下来。

#### 龚银（安克创新 CIO）：一部三年踩坑史，四个阶段

先给底盘数字：**约 5000 人，每天 Token 消耗约 4500 亿**。他特意补了一句很关键的话：**Token 消耗量不代表真正的价值，但它能说明员工拥抱 AI 的深度和广度**。

安克的抓手是「**流程智能体**」（内部叫 PA）：认为 AI 在企业里真正产生价值的部分，是把现有流程做到**单到单的全自动与智能化**。例：告诉它要一个什么产品，**5 分钟**就能出**十几个国家语言**的说明书并直接可打印——从产品提炼、当地法规审核、内容生成、图片排版全自动。目前覆盖产品研发、供应链、营销服务、HR、法务、质量等，共**800 多个流程智能体**，其中不少是多智能体协同。

AI 原生应用侧：智能客服覆盖**100 多个国家和地区**，7×24 小时邮件/聊天/电话，**AI 托管率 60%+**；另有智能投放、网红营销策略匹配与自动执行；内部自建 AI 文档体系与会议体系。

他把三年拆成四个阶段，这是全场最有复用价值的一段：

| 阶段 | 当时最大的坎 |
|---|---|
| 2023 | 怎么让 AI 找到合适场景落地产生价值，从而**让大部分人相信 AI 有用、愿意拥抱** |
| 深入应用期 | 怎么让 AI **深度融入业务流程**——不是「我去用一下工具」，而是处理业务时背后就有 AI 驱动；以及**全公司的 AI 友好化**（数据、流程、知识、人员、组织都要适配 AI） |
| 第三阶段 | **AI 基建**：数字化基建不好、数据体系差、数据质量差、流程没定义、隐性知识没被剥离出来——大模型再好也产生不了企业价值 |
| 2025 | 云与 AI 的整体转型、**组织的 AI 变革** |
| 2026（现在） | 两个技术门槛 + 一个组织门槛（见下） |

现在的两个技术门槛说得非常具体：

1. **Harness 与质量门禁**：AI 写得太快——**一天能写 10 万行代码，但人 review 不过来**。**人已经成了 AI 执行速度的严重阻碍**。所以第一件事是**把人从 loop 里挪到环外**。但不同领域（研发、运营、营销）的评估体系、质量门禁不一样，缺的是**通用范式与可快速放量的能力**；
2. **Agent 的身份与权限**：内部大量 Agent 在背后自动感知、决策、执行。它到底以**用户角色**、以**岗位角色**，还是以**一个全新角色**行事？边界怎么界定？

组织门槛他用了「战斗机」的比喻：大模型是先进生产力，是战斗机；但**没有飞行员，战斗机没用**。所以要花大量时间把员工转型成「懂业务 + 懂 AI」的飞行员。可下一个问题更尖锐：**每个人都变强了，组织效率就更高了吗？不一定**——因为现在的组织结构是工业时代的**分工协作**结构，一个人做一件事。而 AI 时代一个人可以做很多事（写代码、做视频、写音乐），**以前的岗位还有用吗？**

安克的实际动作：岗位合并、把长链路协作改成**短链路协作**、组织微型化——**把 5000 多人拆成 1000 多个 5–6 人的小组织**，在 AI 与大量智能体协同下发挥更高效率。终局形态他希望是「**动态蜂巢式**」：自我感知、自我修复、自我协作，自动完成目标。

#### 李朝明（西门子 IT 亚太区数据与 AI 负责人）：数据不缺，缺的是模型上限

他的开场很有意思：**大家缺什么想什么**。西门子数字化转型很早，数据不是大难题，所以反而更看重模型能力：

> 大模型和应用场景是 **1 和 0** 的关系。模型能力不提高，后面的工作最多是锦上添花。

已跑通的场景：

| 场景 | 说明 |
|---|---|
| 工控代码生成 | 全球推出的工程 Agent 可在工控领域自动生成 **PLC 与 HMI 代码**，并完成**生成 → 校验 → 部署 → 测试**（follow 标准开发逻辑，测试通过才进生产） |
| AI Coding | 部分领域**AI 代码率超 50%**，有些 team 完全通过 AI Coding 完成 |
| 私有知识问答 | 全球 7×24 客服机器人「**小溪**」（西门子私有知识，通用大模型没训练过）；内部办公平台「**小雨**」连接内部知识与数据，支持 Agent 与数字人部署，**白领渗透率超 70%** |

做不到位的三件事，讲得很坦白：

1. **高精准度场景不稳定**：如 KPI 分析，准确度时高时低；
2. **生产控制领域精度不够**：那里「1 就是 1、2 就是 2」，稳定度仍有欠缺；
3. **CV 多模态泛化与迁移能力不强**：新场景都要重新训练，时间长、成本高，大规模落地困难。

组织侧他补了西门子的特殊性：**178 年的企业、全球 30 多万员工**。他的立场是——AI 未来可能是一辆汽车甚至超级变形金刚，但**人类还是希望能驾驭它**，所以组织转型的核心是让每个人都理解 AI、使用 AI，最终**驾驭** AI。战略上，西门子三年前已把自己重新定义为「**One Tech Company**」，要从工业公司转型为科技公司，并带着 30 万同事一起转型。

> 现场还有一个高价值信息：李朝明透露，在做全球技术战略选型时，已把**阿里云 + 千问大模型 + 百炼 MaaS + Qoder** 列为**全球 AI 技术基础设施的标准方案**。

#### 王云鹤（基元律动创始人 & CEO）：一个 4 月成立公司的反面教材

他是全场唯一「没有存量资产」的样本——公司 4 月刚成立，Day 0 就做 AI native 团队。

**踩坑一：六个人用 AI 写代码，合不到一起。**
6 个人分头用 AI 写一个大项目，每个人都写得很好，每个人都觉得 AI 太厉害，**最后发现六个人写的代码合不到一块去**。他去请教一位 2017 年就做 AI Coding 的软件工程前辈，得到的建议是：**软件工程的架构不能完全交给 AI**，需要先做详细的精细化拆解，再让 AI 去做。

**踩坑二：魔法对魔法。**
「我用 AI 写一个，你用 AI review 一下，**魔法对魔法**，最后也不知道谁对。」直到有研发同事说「AI 写的代码太强了，但最后报错了我也不知道它哪里写错了」。

**踩坑三：Deep Research 的「蓝色小条条」。**
4–6 月大家觉得泛科研类 Deep Research 特别好，每天讨论都用 PPT/HTML。但到后来——**看到那个蓝色小条条就知道是哪个模型生成的**——大家开始对 AI 产生抵触。他的解法很朴素：**多参加 workshop、多跟人聊，让 Deep Research 多一点「活人感」**，避免长时间陷入与 AI 的对话形成信息茧房。

他对「坎」的判断也和别人不同，而且更尖锐：

> 第一道坎还是**贵**，Token 太贵了。第二道坎是**模型月更**——谁能保证自己手里的 API Key 每个月都用到最好的模型？第三道坎是**公有云与私有云的业务冲突**，再新的企业也不希望所有数据对外开放。

他还讲了一个真实观察：团队发 OpenRouter 额度，本以为大家会用 Qwen-Max，结果**真实刚需是 Flash 模型**。而他对成本与能力甜点的判断是「**27B + Flash**」这两个档位——这也解释了为什么他说「看到 Qwen4 的计划之后我放心了」。

#### 曹通易（元戎启行 CTO）：物理 AI 不接受「锯齿状智能」的短板

底盘数字：产品是**物理 AI 模型**，落地高阶辅助驾驶，已搭载**超 50 万辆**车，**每天产生上千万公里**智驾里程，模型部署在**端侧车上的小芯片**。

他认为大模型对元戎有两层意义：

1. **产品本身就是模型**：智驾从传统模块化 → 端到端深度学习 → 今天的大模型驱动架构。2024 年他们看到 Transformer 的拟合能力与数据吸收能力后非常兴奋——泛化、安全性、拟人程度都强了很多；研发范式也从「人标数据 + 类 CV 训练」变成**预训练 + 中训练 + 后训练**；
2. **「工厂」本身也在用大模型**：传统模型生产靠数据闭环（问题识别、场景分类、数据挖掘、训练验证），大量研发人员参与，本质是提供**对自动驾驶场景的认知**。现在可以用千问的云端超大规模多模态能力，加上自有 in-domain 数据 fine-tune，让模型对物理世界场景做出好判断——**这有点类似 RSI（递归式自我改进）**。他认为这部分「大家看不到，但对研发效率的意义更深远」。

他对风险的态度是全场最严的：

> 我们希望研发效率提升，但**安全性与模型的靠谱程度不能因为引入大模型而发生任何标准妥协**。大模型可能有幻觉，但物理 AI 世界的模型**一定是严谨的**——有确定把握的地方才做，不确定的地方它要知道自己不能做。

他点出组织用 AI 的两个极端：要么很保守不愿试，要么觉得模型无所不能、**把自己的脑子交给模型，自己变成模型的手**。两者都会给研发流程引入问题。所以关键原则是：

> 模型是**锯齿状的智能**——有些地方非常强，有些地方非常弱，而且 2024/2025/2026 的边界一直在变。必须**在研发流程里适配模型能力去引入模型**，用自己的 in-domain 数据 fine-tune，确认具备足够的 in-domain 能力之后，才敢用到生产环境。

#### 一人一句：五位嘉宾给企业客户的建议

| 嘉宾 | 建议 |
|---|---|
| 陈炯 | 先解决**对大模型的恐惧**。AI 更强人也得更强——如果 AI 说什么你都 yes，你就没价值了。要提升专业度、对方案的**判断力**与**审美** |
| 龚银 | ①**临渊羡鱼不如退而结网**，一定下场游泳，别站岸边看；②模型大家都会有，真正要建的是**企业自己的 Context 基础功** |
| 李朝明 | **四大**：大数据（放到一起才有大价值）、大模型（能用大就不用小）、大生态（找最合适的人做，各自聚焦独特价值）、大时代（加入它） |
| 王云鹤 | **先有人工再有智能**——数字化、信息化做好，再谈智能化；**千万别什么都想做**（要聚焦，聚焦也意味着 Context 要写得更精准） |
| 曹通易 | AI 能力进展很像自动驾驶的 L2→L3→L4：**能力不同，该给的 scope 就不同**。L2 的能力却让驾驶员睡觉，一定出问题。既要有「模型终将进步」的信念，也要严谨考证**它的能力边界在哪** |

徐栋的收尾也值得记：**「模型变化实在太快，我们往往只能预测未来 1–2 个月的事情。」**

### 4.8 张轲（MaaS 业务线全球战略伙伴负责人）《全球能力，本地增长》（198:01–211:56）

#### 命题的升级

过去：全球产品能否部署到本地市场（基础设施适配、合规准入、数据本地驻留）。
今天：

> **全球产品的 AI 能力，能否进入客户的真实环境，成为客户愿意买单的产品，并在本地市场实现持续增长？**

他给出 Agent 时代的三处变化：

| 变了什么 | 从 | 到 |
|---|---|---|
| **使用者** | 只有人操作软件 | 软件也会被 **Agent 调用**——API、数据权限、业务动作都必须能被 Agent 安全理解、编排、调用 |
| **客户判断标准** | 模型性能、参数、功能 | **实际业务结果**：缩短业务周期、减少错误、提高转化、带来新收入 |
| **竞争壁垒** | 功能与体验 | 能否做到 **Agent Ready**——能否被 Agent 持续调用和操作 |

结论句：**Agent 时代不是一次简单的技术升级，而是对产品形态、客户价值和产品竞争优势的重新定义。**

#### 合作三阶段路径

| 阶段 | 做什么 |
|---|---|
| **AI 产品化** | 集成千问大模型与千问 AI 平台的模型服务能力，让伙伴全球产品的 AI 能力顺利落地，同时**保持与全球产品能力一致**并兼顾本地需求 |
| **Agent 生产化** | 平台提供一站式 Agent 开发、编排、管理能力，连接丰富第三方服务与数据，推动 Agent **从 Demo 走向生产** |
| **市场规模化** | 共同打造联合解决方案、树立标杆、联合销售与市场推广，把**一个客户的成功沉淀为可复制的增长模式** |

#### Salesforce：从「人的工作台」到「人与 Agent 协同的业务平台」

CRM 不再只是供人操作的系统，而是被 Agent 安全调用、灵活编排、能自主执行的业务平台。Salesforce 通过 **API、MCP、AI Actions 与技能体系**，把 Customer 360 中的客户数据、业务逻辑、操作能力**有序开放给 Agent**。

阿里云上的 Salesforce 具备「智能体企业」的**五层关键能力**：

| 层 | 内容 |
|---|---|
| 模型层 | 千问 AI 平台提供 Qwen-Max、Qwen3.8-Max 等丰富模型服务，也支持客户接入自有微调模型——**模型怎么选、如何组合，决定权始终在客户手中** |
| 数据层 | 打通客户数据平台，与主流数据产品多样化连接，把分散数据汇聚成**统一可信的业务上下文** |

#### 李奇颖（SAP 中国，阿里巴巴战略合作总经理）：为什么一家「传统软件公司」站上 Agent 主论坛

他的开场自问自答很有说服力：

> 当 Agent 真正要进入财务、采购和供应链时，**光有模型能力是不够的**——它还要理解企业的数据、企业的语义，遵循权限、流程和合规要求，并且真正推动业务执行。SAP 50 多年积累的正是这些核心流程、业务规则和企业数据。

SAP 的概念是「**自主运营企业**」：让 AI 从回答问题走向参与运营。

他对 ERP 与 Agent 关系的判断很清醒：

| | 传统 ERP | Agent 时代 |
|---|---|---|
| 逻辑 | 把采购、财务、供应链、制造数字化，业务逻辑写入系统，**人按流程操作**，系统记录/校验/执行 | ERP 可以**感知业务变化**、结合上下文推理、**在权限边界内做决策**，跨系统调用工具，在核心流程完成自主闭环 |
| 前提 | **每一步都需要人触发、判断、推进** | 改变的是**人与系统的分工** |

所以他的结论是：**Agent 时代不是抛弃 ERP，而是让 ERP 从「记录业务」走向「理解业务、推动业务」**。

合作的互补性讲得很清楚：SAP 带来 50 多年管理知识、核心流程与行业语义、企业数据治理框架、企业 AI 与应用产品体系；阿里云带来千问大模型、百炼平台、大规模 AI 基础设施、中国本地合规与生态交付。**两家在各自领域深耕多年的公司，在这个窗口形成了结构性互补**。

案例是**牧原肉食**（中国最大的农牧企业之一）：毛利异常时有发生，过去从发现、定位到根本原因要**数小时**——人跨系统查数据、逐项对比、层层上报审批。现在 Agent 实时监控关键经营指标，发现异常自动预警、调取 SAP 明细数据、完成根因分析、直接生成整改建议。

| 指标 | 变化 |
|---|---|
| 响应时间 | 数小时 → **5 分钟** |
| 监控范围 | 扩展至 **10 个经营模块** |

他的落点：这不仅是效率问题，它说明 **Agent 已经能在企业 ERP 的核心流程里承担实质性的分析与决策辅助**。

### 4.9 刘丽娟（MaaS 业务线产品生态发展部总经理）《AI 产品生态》（218:39–232:22）

#### 一个判断：企业从「自建」转向「采购成熟产品」

她观察到客户问题的变化：不再是「我要不要用 AI」，而是「**AI 到底能不能解决我实际的业务问题、能不能带来可衡量可看见的业务结果**」。

供给侧也在变。过去企业因为市场上缺 AI 应用只能自建；过去一年，**越来越多企业从自建 AI 转向采购成熟的 AI 产品**，用标准产品加少量克制（定制）来加速落地。

她给了一组供给爆发的数字：

|---|---|

#### 一次升级：云市场 → AI 应用市场

原阿里云云市场已服务成千上万客户，但「这个品牌已不足以承载我们与客户、伙伴共同创造的新价值」。于是正式升级为**阿里云 AI 应用市场**，新增：

- **产品类型**：模型、MCP 等；
- **付费类型**：按席位、按 IT、按 AI 资源包、按小时、按分钟。

存量底盘：**2000 多个伙伴、8000 多个商品、每年服务 40 万客户、带来 270 万个订阅**。

「选、买、用」三段的机制：

| 段 | 机制 |
|---|---|
| 选 | **AI 选品**（自然语言输入，自动匹配满足业务需求的产品与方案）+ **AI 精选频道**（甄选优秀 AI 产品） |
| 买 | **透明交易链路**：从买到交付到付款到发票全程可见——客户清楚知道「买的是什么、用到了哪里」 |
| 用 | **免费试用**，以极快速度、极低成本获得产品 |

#### 繁花计划 2.0

1.0 阶段围绕伙伴产品商业化设计成长链路：技术验证 → 打包上架 → 商业化设计规划 → 商机拓展 → 标杆客户打造 → 规模化复制，每阶段提供相应支持，形成销售闭环。

2.0 的三处扩展：

| 扩展 | 内容 |
|---|---|
| **更多露出与销售路径** | 除 AI 应用市场，还可推到**千问 AI 平台、百炼、Qoder** |
| **国内外打通** | 同一产品可面向全球客户做覆盖与营销 |

她的收尾是生态视角的实话：合作给伙伴带来的不只是市场增量与新客户，更重要的是**帮他们打磨了产品在 AI 环境下落地客户真实场景的经验**。

## 七、五个可复用的判断

1. **单价下降 ≠ 产业通缩，这是本场最值得带走的一句经济学判断**。看「每百万 Token 多少钱」是看资源成本；看「智能价值密度 = 单任务价值 × Token 生产效率 × 单 Token 能力」才是看价值创造。这个框架可以直接用来评估任何 AI 产品线的定价策略。
2. **企业级 Agent 的真正瓶颈不是模型，是上下文与企业语义**。陈宇森那组「古茗左右对照」是最好的证据：右侧问题任何 Chatbot 都能答，左侧问题只有懂企业的 Agent 能答。所以「懂业务」不是体验优化，是准入门槛。
3. **AI Coding 的竞争单位已经从「代码」上移到「任务」**。Qoder 的三个数字（30% 非专业开发者、50% 非编程任务、80% 代码由智能体写）共同说明：产品形态必须从「帮人写代码」变成「帮人定任务、验收结果」。而 **Code Security 从规则扫描转向模型内生**，是这个转变的必然配套。
4. **人正在从 AI 的执行环里被「请出去」，而这一步比模型能力更难**。龚银说得最直白：一天能写 10 万行代码，但人 review 不过来。真正要解决的是**质量门禁与评估体系的通用化**，以及 Agent 的**身份与权限边界**。
5. **组织形态会成为比模型更硬的天花板**。安克把 5000 多人拆成 1000 多个 5–6 人小组，是在回应一个真问题：每个人都变强，组织效率不一定更高。西门子则从另一侧证明——178 年、30 万人的公司，转型的难点在于让人**驾驭** AI 而不是被替代。
