# 阿里云电力 AI 调研（七）：横向能力——Agent 工程化的五个关键设计与成熟度天花板

> 本系列共八篇，逐环节拆解阿里云在电力行业「发、输、变、配、用」的 AI 与 Agent 落地现状。
> 全部结论标注信源等级：**A** 官方（阿里云/客户官网、官方技术博客）、**B** 权威媒体 / 行业白皮书 / 信通院、**C** 厂商 PR 稿或会议演讲、**D** 二手转载（仅作线索）。
> 本系列刻意区分「已投产」与「方案宣传」，并对厂商口径保留独立判断。

前六篇按「发、输、变、配、用」逐环节拆完了阿里云在电力行业的落地。六篇读完得到的是一堆互不相干的印象——山东的调度智慧大脑、广东的计量设备 AI 指挥官、冀北的操作票校验、浙江的 AI 评标、国家管网的管输路径智能体。并排放置后能看到一个更值得写的事实：它们共用同一套技术底座（飞天企业版 + 百炼专属版），也共用同一套 Agent 工程方法论——大小模型协同、图模融合、确定性校验、人机责任边界。单看某一项目只是「某省电力的某次试点」，横向看，它们才是真正可复制的那部分资产。

第二层动机是祛魅。电力 AI 材料里，「百余个智能体」「自学习自优化」这类表述密度极高，但它们描述的是**规模**与**路线图**，不是**自主度**与**交付状态**。本篇把案例逐一映射到自建的三档成熟度分级上，结论先给：电力行业公开可验证的 Agent 天花板是 L2（工具调用闭环），全行业没有 A/B 级信源证明 L3（多智能体自主协同决策）已落地。

## 一、三层架构与核心产品清单

把阿里云在电力行业的产品按「谁依赖谁」排一遍，得到三层结构：底座层给算力与数据，平台层给模型与工具链，应用层是业务场景的智能体。上层的能力上限由下层决定。

### 1.1 算力与数据底座层

关键词是「同根同源」与「混部」。飞天企业版是阿里云的专有云形态，官方表述为与公共云同根同源、基于同一套飞天云计算操作系统，为政企客户构建资源与云管完全独立的企业级云平台（A）。三组能力值得记下：

- **一云多算**：智算（GPU）+ 超算（高性能 CPU）+ 普算（通用 CPU）融合为异构算力集群，通过算力池化做多租户隔离（A）。
- **一云多芯**：支持 Intel、海光、鲲鹏、飞腾、倚天 710 等芯片混部，并支持在线轮转——不铲除、不重建地在线替换服务器（A）。对停机窗口极稀缺的电网机房，这比参数更有价值。
- **规模化能力**：官方口径为单集群最大支持 1.5 万张 GPU 卡、资源按 1% 粒度调度、GPU 利用率提升 100%、百万 Output Token 成本下降 89%（C，厂商口径；「提升 100%」是相对基线的倍数表述，不是「达到 100%」）。

电力专用算力有两个标志节点：2021 年 8 月南方电网与阿里云上线的国内电力行业首个云超算平台（南网调度云超算），采用飞天 + 神龙超算集群，每秒 825 万亿次浮点运算，单节点性能较普通云服务器提升 5 倍（A）；国网云，国家电网自 2019 年起构建覆盖全国的超大型云计算平台，核心由阿里云提供技术支撑（B），2020 年共建时用的是飞天企业版「一云多 Region」能力（A），该平台后来成为光明电力大模型的数字底座。

数据侧两个落点：龙源电力用阿里云大数据组件与 OneData 建数据挖掘服务系统、用 ACK 搭建覆盖 700+ 节点的统一管控平台（B，2022 年口径）；AI Stack 一体机单机 16 卡、1.5TB+ 显存、机间 1.6Tbps 带宽，可作边缘节点接入飞天企业版形成云边一体（C）。

### 1.2 模型与平台层

核心产品是百炼专属版：面向政企客户、支持国产算力、跨模态的行业大模型与智能体平台，提供知识管理、模型训练与微调、智能体搭建、能力评测的一站式工具链（A）。三个规格需分清（A）：MINI 是单机一体机，开箱即用 DeepSeek + Qwen 的企业专属 RAG；Lite 与标准版是集群版，面向需自定义搭建的政企客户。模型侧预置通义 7B 到 72B 的多尺寸大语言与多模态模型，支持三方模型自定义接入；数据侧覆盖图表、公式、图片、音视频及大文件解析，共 30 多种结构化与非结构化数据（A）。与公共云百炼的差别不在模型数量，而在部署环境（公共云 VPC + 专有云双形态）、算力（支持国产算力、异构 GPU 统一管理与混合推理调度）与计费方式（买断或软件授权 + 硬件，而非按 Token 计费）（A）。另有两个常被忽略的组件：达摩院八观气象大模型，在山东调度智慧大脑中把未来 48 小时气象预报更新频率提升到 1 小时一次（B）；以及智能体中心与全模态知识数据中心（A）。

### 1.3 智能应用层

前六篇已逐个拆过，此处只做清单收口：

- **电网调度智慧大脑**（国网山东 + 阿里云 + 达摩院 + 南瑞）：2024 年迎峰度夏 7 次极端天气下负荷预测平均准确率 95.72%，节假日 99%；故障研判 1 分钟内出结果；覆盖 400V–1000kV 数字孪生体（B + A）。
- **国网云智**（2025 年 6 月上线）：问答、定位、检修方案生成三大能力，知识覆盖率与召回率 80%，异常定位与方案编写效率各提升 40%（A）。
- **计量设备 AI 指挥官**（南网广东电网）：AI 巡视 / 检验 / 运维 / 日报四智能体闭环，工单处置效率提升 8 倍，故障自愈率 80%（B）。
- **光明物资评标大模型**（国网江苏）：客观项自动评审 + 主观项人机协同，评审效率提升 4 倍以上（D，待二次核实）。
- **擎源发电大模型**（国家能源集团）：15 个业务领域、75 个应用场景、部署百余个智能体（C）。
- **管网管输路径智能体**（国家管网）：基于通义千问建油气行业专属知识库，AI 推荐最优路径，需求提报效率提升 60%，紧急调运秒级响应（C）。

## 二、Agent 工程化的五个关键设计

把五个环节的项目拆到实现层，可复用的工程模式只有五种，且每一种都同时出现在两个以上案例里。

### 设计一：大小模型协同——大模型不碰数值

山东调度智慧大脑的机制是「大模型 + 机理模型」协同（A）：大模型充当**指挥中枢**，沿「问题定位 → 影响分析 → 方案建议」的思维链推演，组织各类小模型协同工作；小模型负责**精准计算**，为大模型提供准确数据。两者之间用统一数据格式与标准接口保障信息流通（A）。关键在于分工的不可替换性：大模型不做数值计算，潮流、稳定、约束求解交给机理模型与优化求解器。江苏无人机巡检用同一范式——小模型定位缺陷，大模型研判等级（C）。效果量级有一次交叉验证：48 小时气象预报更新提升至每小时一次后，两次转折性天气的负荷预测准确率达 99.13%，较传统方式高 2.15 个百分点（B）。

### 设计二：图模融合——知识图谱的生态位是「兜底」

山东调度用「图（知识图谱）模（大语言模型）融合增强」技术解析操作票内容，自动匹配检修申请与电网拓扑，实现操作票全要素智能审核，演化为「虚拟安全员」；调度员反馈：过去只能识别「带地线合闸」这类基础错误，现在连「漏投短引线保护」这类复杂问题都能发现（A）。国网冀北的同源实践是操作逻辑规则库 + 设备知识图谱构建「AI 成票 + 智能校验」，开票准确率 90% 以上（B）。方法论抽象：图谱在本调研覆盖的全部案例里只出现在强安全操作类业务（操作票、工作票）中，它的分工是**结构化强校验（刚性）**，大模型负责**语义推演与隐性风险识别（柔性）**（C）。也就是说，知识图谱的真实生态位不是「给大模型喂知识」，而是**给大模型兜底**。

### 设计三：智能体中心与工具链

百炼专属版的智能体中心提供一站式开发范式与工具链，用于应用之间的集成与对接（A）。工作流内置开始/结束、大模型、知识库与向量检索、MCP、API 插件、函数计算、条件判断、意图分类、循环、批处理、参数提取、智能体群组、多模态解析与生成、数据连接器等 20 多个节点（A）。飞天企业版 PaaS 层融合 Model / MCP / Agent 网关，存量接口零代码转换、集成成本下降 90%，兼容向量、图、时序、时空等 10 类 AI 数据模型，集成 80+ 插件（C）。这一层的意义不在节点数量，而在于把「编排」从代码变成配置——这是 Agent 能进运维现场的前提。

### 设计四：RAG 知识工程

阿里云口径的 RAG 落地是一条完整链条：多格式解析 → 术语标准化 → 知识库构建 → 检索增强生成 → 专业模型针对性训练。起点是解析广度，百炼专属版支持 30+ 种结构化与非结构化数据解析（A）；中间是术语库工程，把电力行业术语库与调度规程文档库加工成模型能理解的专业知识，专业术语识别准确率提升至 98%（B）；终点是检索质量，国网云智的全栈云产品知识覆盖率与召回率达 80%（A），国网冀北以光明电力大模型 + 知识增强支撑作业卡智能填报，填报时间由约 1 小时缩短至分钟级（B）。98% 是这条链路上唯一被反复引用且口径稳定的量化指标；而 80% 的覆盖率与召回率说明瓶颈仍在「覆盖」，不在「检索算法」。

### 设计五：高风险决策的边界——评标场景的三条线

国网浙江的 AI 辅助评审：单本标书阅标 1–2 分钟，人工至少 20 分钟；更值得关注的是 **AI 智能赋分与专家人工赋分的吻合度 82.16%**（B）。这个数字同时暴露了上限——约 18% 的赋分上 AI 与专家不一致。在直接决定中标人的场景里，18% 的分歧率足以证明 AI 赋分不能作为最终分，必须经专家复核；「准确率超 95%」这类单一口径数字的信息量要低得多，因为它的分母无从检验。

由此归纳出三条边界：定位上，官方名称是「**辅助**」评标，AI 负责翻得快、看得细、比对狠、留痕全，不替专家定标；任务上，客观项（资质是否过期、业绩是否够数、人员证是否齐全、报价是否算错）规则固化后自动比对，主观项（技术方案、施工组织、服务思路）AI 不打分，只做同屏对比、关键点高亮并给出参考分，专家改分留痕；留痕上，走「AI 智能评审 + 专家复核研判」模式，专家重心转向关键技术参数研判、疑点甄别与结果复核（B）。

## 三、幻觉不是靠更好的模型解决的

核心判断只有一句：电力行业消化大模型幻觉的方式，不是换一个更强的模型，而是在模型外挂一条确定性的校验流水线。

正面案例是国网冀北：针对 AI 生成的操作票，建立「**逻辑校验、五防校验、术语校验、历史票校验**」四重验证机制，形成从逻辑合理性到安全规范性的多层防护，经多轮测试校验后票面内容准确性达到 100%（B）。必须注意成立条件——这是**四重校验之后**的准确率，不是模型裸输出的准确率；拿掉校验层，这个数字不成立。

反面证据来自学术与行业期刊，三份独立信源指向同一组硬约束：中国电力科学研究院期刊指出五大局限——输出幻觉、数学与逻辑推理有限（最优潮流、状态估计难以替代传统优化算法）、黑盒不可解释、异常样本极度稀缺且分布不均衡、训练部署推理成本高（B）；MDPI《Energies》综述明确 LLM 是概率系统，直接协调物理设备时形式化验证层、确定性回退机制与 human-in-the-loop 不可或缺，且已证实针对智能电网部署的 LLM，坏数据注入与领域知识抽取攻击可行（B）；IEEE Xplore 指出电网企业存在跨机构「数据饥荒」，集中训练违反隐私与监管约束，联邦学习仍受梯度泄漏与推理攻击威胁（B）。

工程上这条流水线长这样——把校验做成独立于模型的工具，由编排层强制调用，失败即回退：

```json
{
  "tool": "operation_ticket_verify",
  "type": "deterministic",
  "input": ["操作票条文", "检修申请", "电网拓扑快照"],
  "checks": ["logic", "five_prevention", "terminology", "history"],
  "output": ["违例项", "缺失项", "证据链"],
  "on_fail": "return_to_llm"
}
```

这与设计二的图模融合本质相同：都用规则与图谱兜底，差别只在位置——图模融合把兜底放在推理中途，四重校验把兜底放在输出之后。**可信 AI 的增量不来自模型，来自模型之外。**

## 四、Agent 成熟度分级：电力行业的真实天花板

需要先声明：L1–L3 分级是本调研自建的判断框架，不是行业标准——公开渠道没有找到电力行业 Agent 自主度的分级规范（未找到公开信源）。分级的意义在于把「数量」与「自主度」两个常被混用的维度拆开。

- **L1 单点问答（弱）**：有 RAG，无工具调用或仅只读检索；输出是「信息」而不是「动作」，不改变业务系统状态。
- **L2 工具调用闭环（中）**：能自主规划并调用外部工具、API、小模型，形成「感知—分析—建议/派单」闭环；输出驱动业务流转，但最终动作需人确认。
- **L3 多智能体自主协同决策（强）**：多智能体分工协同，具备自学习/自优化，能生成运行策略；输出可直接影响物理系统或关键决策。

## 五、国产化栈的实际约束

客户侧的国产化路径已经跑通，但有明确的代价记录。

已落地的事实（B）：国网山东电力走「全栈国产」路线，硬件层采用全国产 GPU 算力集群，项目团队攻克的重点难题之一是「**芯片指令集架构与大模型框架不兼容**」；南网广东电网构建核心计量系统时，从服务器、操作系统到数据库均采用国产化组件，联合阿里云仅用三个月完成 800 台国产服务器部署；国网浙江的 AI 辅助评审依托省级 10 台 910B 昇腾算力服务器集群。

产品侧承诺（C，厂商口径）：飞天企业版一云多芯支持 Intel、海光、鲲鹏、飞腾、倚天 710 等芯片混部，一云多算实现 CPU、GPU 等不同算力的统一调度，官方称「将资源利用率提升 100%」——同样是相对基线的倍数表述。

需显式标注为**行业估算口径、非权威实测**的三项（D 级，多为二手引述或厂商周边自媒体的综合估算）：「迁移成本」84% 的企业原有 AI 业务基于 CUDA 开发，切换昇腾原生 CANN 环境的代码改造成本平均提升约 62%，单项目迁移工时超 120 人天；「性能差距」昇腾 910B 在 7B 模型训练上约为 H200 的 80–85%，推理约 85–90%；「单位成本」一台 8 卡昇腾 910B 一体机约 130 万元，因显存较小，部署满血版 DeepSeek 至少需 2–4 台。

这三项在本系列中**不能作为官方数据使用**，只能作量级参照。它们唯一的价值是提示一件事：国产化不是零成本的开关，而是一次有明确工程代价的迁移——「不兼容」三个字出现在官方报道里，本身就是最有力的一手证据。

## 六、一个必须点破的事实：客户侧是解耦的

这是全系列方法论的基石，也是最容易被厂商叙事掩盖的一点。

第一，**光明电力大模型是多供应商的**。宁夏日报（B）的表述是，光明大模型「由阿里巴巴、百度等提供技术支持」；国网宁夏信通公司「将进一步开展电力大模型平台、阿里百炼、百度千帆的部署验证工作」。也就是说，国网采取的是多供应商并行验证策略。

第二，**算力、模型、平台在客户侧是解耦的**。国网浙江的 AI 辅助评审跑在昇腾 910B 集群上，而模型是光明电力大模型。模型供应商（含阿里）、算力供应商（昇腾）、平台供应商（百炼专属版为其中之一）可以是三家不同厂商。

由此推出两条写作纪律：不能把国网写成「用阿里云全栈」；也不能把「光明电力大模型」的成果单方面记到任何一家技术供应商账上。这既是客观性要求，也是整个系列可信度的来源。

## 七、成本信息的公开缺口

必须承认一个事实：百炼专属版与飞天企业版**没有任何公开报价**。官方渠道仅提供「获取报价单」的表单入口，公开页面上找不到价格（未找到公开信源）。

能查到的只有第三方量级（C / D，非官方）：私有化部署的三条路径中，AI 一体机落在数万元至 200 万元级，开源自建数十万元起；大型央国企的 AI 预算一般落在 200 万–500 万元区间，中小型机构较易批复的在 100 万元以内、集中在 10 万–50 万元。此外，开源自建方案的隐性成本（运维人力、故障处理、能力培训、二次开发）可能显著超出初始预算（C）。这些数字全部来自第三方自媒体或咨询转述，没有阿里云官方或客户官方口径，因此本系列的成本段落只能写量级，并必须标注为非官方估算。

## 小结

第一，横向看，阿里云在电力行业的可复制资产不是某个具体应用，而是三层底座加五个工程模式：大小模型协同解决「算得准」，图模融合解决「校验得住」，智能体中心解决「接得进」，RAG 知识工程解决「读得懂」，高风险决策边界解决「敢不敢用」。前四个是能力，第五个是纪律。

第二，能力已经到位、纪律也已写进方案，但自主度必须按事实陈述：公开可验证的落地停在 L2（工具调用闭环），L3 仍以路线图形式存在。「百余个智能体」是数量口径，不是自主度声明；「自学习、自优化」目前在电力行业的时态是将来时。

第三，客户侧的算力、模型、平台是多供应商解耦的。这决定了本系列的结论只能是「阿里云是光明电力大模型的全栈技术支持方之一」，而不能写成「国网选择了阿里云全栈」。
