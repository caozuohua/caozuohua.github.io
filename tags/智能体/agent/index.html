从零到一：基于 Gemini 和 Claude 的智能体开发实战——集成 Vertex AI、Lark、SQLite，赋能动态工具与持久记忆

引言

在个人开发者资源有限的情况下，如何构建一个功能强大且具备学习能力的智能体？本项目将带您深入探索，如何利用免费资源（VPS、AI模型、Lark机器人等），从零开始，一步步打造一个集成了 Vertex AI、Lark、SQLite，并支持动态工具库、持久记忆和偏好学习的智能体。整个开发过程，我们将全程依赖 Gemini 和 Claude 这两位强大的 AI 助手，通过不断的对话、调试和代码生成，最终成功实现这一目标。

背景与挑战

1. 资源限制与成本考量

对于个人开发者而言，有限的 VPS 资源和对 AI 服务成本的考量是首要问题。本项目旨在使用尽可能免费或低成本的方案，证明个人开发者也能构建出色的 AI 应用。

2. GCP 模型列表更新与教程失效

在开发过程中，我们遇到了 Google Cloud Platform (GCP) 的 Vertex AI 模型列表更新的问题。许多基于旧模型列表的网络教程和示例代码因此失效，增加了我们查找和适配最新可用模型的难度。

3. Lark 机器人事件回调配置难题

国际版 Lark 机器人的事件回调配置，尤其是在添加各种自定义事件时，缺乏清晰的指导步骤，给开发者带来了不小的挑战。我们需要自行探索和摸索其接口和配置方式。

开发过程与解决方案

1. AI 助手的协同开发

  • Gemini 与 Claude 的角色分工： Gemini 在项目初期提供了整体的架构设计思路和技术选型建议。而 Claude 则在具体的代码实现、问题排查和模型接口探索中扮演了关键角色。
  • Claude 的代码生成与调试： 面对 GCP 模型列表的变更和 Lark 机器人的配置难题，Claude 不断地编写测试代码，帮助我们摸清模型清单、回调接口的细节。从 API 调用、参数配置，到实现偏好系统、记忆系统、动态工具库，Claude 提供了大量的代码支持和调试建议。

2. 技术栈选择与实现

  • VPS: 利用免费或低成本的 VPS 作为运行环境。
  • Vertex AI: 通过 Vertex AI 访问 Google 的强大 AI 模型。
  • Lark: 集成 Lark 机器人，作为智能体的交互界面和事件处理中枢。
  • SQLite: 使用 SQLite 作为本地数据库，实现智能体的持久记忆功能。
  • Python: 作为主要的开发语言。

3. 解决关键问题

  • GCP 模型更新适配： 通过 Claude 生成的测试代码，我们成功地查询并适配了 Vertex AI 的最新可用模型列表，确保了 AI 功能的正常运行。
  • Lark 事件回调配置： 针对 Lark 事件回调的复杂性，我们与 Claude 协作，通过不断尝试和调试，最终成功配置了机器人能够接收和处理各类事件。
  • 动态工具库与偏好学习： Claude 协助我们设计并实现了动态工具库的加载机制，使得智能体可以根据需求加载和使用不同的工具。同时，我们也初步构建了偏好学习系统，让智能体能够根据用户交互逐步优化其行为。
  • 持久记忆系统： 利用 SQLite，我们为智能体构建了持久化的记忆存储，使其能够记住用户的偏好、历史对话等信息，提供更个性化的服务。
