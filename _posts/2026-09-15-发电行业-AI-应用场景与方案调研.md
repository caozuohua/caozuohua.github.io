> 调研范围：火电、水电、风电、光伏及综合能源运营。  
> 检索日期：2025-06-01。  
> 说明：以下将“来源事实”“方案建议”和“待验证项”分开；效果数据仅引用来源披露内容，不将宣传性描述直接视为独立验证结果。

## 一、核心结论

发电行业的 AI 应用可以归纳为四条主线：

1. **设备智能运维**：状态监测、异常检测、故障诊断、预测性维护。
2. **生产运行优化**：智能监盘、燃烧优化、能效优化、运行参数推荐。
3. **新能源预测与调度**：风光功率、来水、电价预测，以及水风光火储协同调度。
4. **安全环保与知识作业**：违章识别、技术监督、规程问答、报告生成、现场作业辅助。

建议采用“**先 Copilot、后审批式 Agent，最后受控自动优化**”的路线：

- 第一阶段：只读数据、知识问答、报告生成、告警解释；
- 第二阶段：生成检修建议、工单草稿、调度/报价草案，由人工审批；
- 第三阶段：在数字孪生、仿真和硬约束保护下进行受控优化；
- 不建议让通用大模型直接写入 DCS/PLC 或自主执行高风险控制操作。

国家能源局披露，国家能源集团“擎源”已覆盖安全环保、电力交易、产调中枢和设备检修四大业务域，覆盖 13 个场景、部署 41 个智能体；但具体部署深度、指标口径和实际节省金额仍需进一步核验。[S1]

# 二、重点场景与方案

## 场景 1：设备状态监测、故障诊断与预测性维护

### 1. 业务痛点

发电设备产生大量 SCADA/DCS 时序数据、振动数据、油色谱、局部放电、红外图像、检修记录和运行规程，但数据通常分散在不同系统中：

- 异常发现依赖人工监盘；
- 故障根因定位依赖少数专家；
- 维修计划仍以定期检修为主；
- 历史缺陷和专家经验难以复用；
- 偏远水电站、风电场现场维护成本高。

### 2. 方案 A：时序模型 + 知识图谱/RAG + 运维 Agent

**推荐度：高，适合规模化建设。**

#### 架构

```text
SCADA/DCS/在线监测
        ↓
数据质量校验与资产主数据统一
        ↓
时序异常检测 / 健康度评估
        ↓
知识图谱 + RAG 检索规程、故障库、检修记录
        ↓
诊断 Agent 生成根因排序与处置建议
        ↓
维护 Agent 生成工单、备件和检修计划
        ↓
工程师审批后进入 EAM/CMMS
```

#### Agent 分工

- **监测 Agent**：识别趋势偏离、异常组合和设备健康度变化；
- **诊断 Agent**：结合实时信号、历史故障和规程，输出候选根因；
- **维护 Agent**：生成检修建议、备件需求和工单草稿；
- **复盘 Agent**：将故障处理结果回灌模型和案例库。

#### 工具与数据

- SCADA、DCS、EMS；
- 振动、温度、油色谱、局放、声纹、红外；
- EAM/CMMS；
- 设备说明书、检修规程、故障库；
- 资产主数据和设备拓扑；
- 知识图谱与向量检索。

#### 人工介入点

- AI 只能提出诊断和检修建议；
- 工单创建、检修范围和停机安排由工程师确认；
- 禁止 Agent 直接下发控制指令；
- 重大设备、核电及涉及人身安全的操作必须双人复核。

#### 适合的 KPI

- 平均提前预��时间；
- 误报率、漏报率；
- 根因 Top-k 命中率；
- 非计划停机次数；
- MTBF、MTTR；
- 工单闭环率；
- 备件库存周转率。

### 3. 方案 B：运维知识助手

**推荐度：高，适合作为第一阶段项目。**

这是一种较低风险的方案：

```text
运维人员提问
    ↓
权限过滤
    ↓
检索设备文档、规程、缺陷记录
    ↓
输出带引用的回答、风险提示和操作步骤
    ↓
人工确认
```

它不直接做实时预测，也不自动诊断设备，而是解决：

- 规程查询；
- 历史故障检索；
- 消缺记录总结；
- 安措危险点提示；
- 检修报告和交接班材料生成。

### 4. 已检索案例

- 国家能源局报道，国家能源集团“擎源”已用于设备状态感知、检修决策和故障根因分析，并在“风光水火储”179 个试点电站应用，半年精准发现缺陷 2633 条。[S1]
- CPEM 报道，国电电力上海庙公司建设了燃煤电厂专属 AI 助手，具备智能问答、智能检索和知识生成能力，并辅助消缺决策、安措危险提示和设备检索。[S3]
- AWS 有 ENGIE 电厂预测性维护案例，说明可利用电厂运行数据进行异常检测和预测性维护，但本轮检索未核验其完整部署边界和量化效果。[S6]
- 昆仑数据披露，其水轮机远程智慧运维系统已经在葛洲坝、安康、李家峡、白鹤滩等 20 多座水电站落地；该信息属于供应商案例披露，具体项目合同和运行指标仍需独立核验。[S4]

## 场景 2：智能监盘、运行优化与燃烧/能效控制

### 1. 业务痛点

火电厂运行涉及锅炉、汽机、辅机、环保和电气等多个系统，运行人员需要持续关注大量参数：

- 异常组合复杂，单一阈值难以识别；
- 煤质、负荷、环境温度变化导致运行策略变化；
- 给煤量、风煤比、氧量等参数依赖经验；
- 运行报告和交接班材料人工编制耗时；
- 直接自动控制存在较高安全风险。

### 2. 方案 A：机理模型 + 时序 ML + 优化 Agent

**推荐度：中高，但必须先在仿真环境验证。**

#### 工作流

1. 读取 DCS/PLC 和燃料数据；
2. 进行状态估计和数据质量检查；
3. 识别效率偏离和异常工况；
4. 在数字孪生或 OTS 仿真环境中生成候选参数；
5. 校验安全边界、环保边界和设备约束；
6. 由值长审批；
7. 通过受控接口下发；
8. 持续监测效果，异常时自动回滚。

#### 适合优化的对象

- 锅炉燃烧；
- 风��比；
- 给煤量；
- 氧量控制；
- 排烟温度；
- 厂用电率；
- 机组负荷跟踪；
- 热电联产供热参数。

#### 控制原则

不建议让 LLM 直接承担底层控制。更稳妥的分层方式是：

```text
大模型：解释、编排、生成候选策略
优化器：计算可行参数组合
机理模型：验证设备和热力约束
控制系统：执行已审批的参数
```

### 3. 方案 B：AI 监盘 Copilot

这是更容易落地的先导方案：

- 读取 DCS 数据，但保持只读；
- 识别参数趋势和异常组合；
- 解释“为什么告警”；
- 查询相关规程和历史事件；
- 生成运行建议；
- 自动生成交接班和运行分析报告。

### 4. 已检索案例

人民网报道，中国大唐宝昌发电公司的智慧辅助监盘系统融合大数据和机器学习，覆盖电厂 24 个系统，能够持续监视设备运行参数、判断设备状态、识别潜在故障并给出指导意见；报道披露模型预测精度和预警准确率达到 94.9%。该数字的测试集、时间窗口和指标定义仍需进一步核验。[S2]

ScottMadden 将发电行业 GenAI 场景归纳为：

- 自动生成工单计划；
- 生成环境报告；
- 利用历史报告、工作计划和记录生成新报告草稿；
- 生产运行知识辅助；
- 设备监测和资产生命周期管理。[S5]

## 场景 3：风光水功率、来水、电价预测与多能协同调度

### 1. 业务痛点

新能源及综合能源运营需要同时处理：

- 风速、辐照度、云量等气象数据；
- 流量、降雨、水库水位等水文数据；
- 设备状态和可用容量；
- 负荷预测；
- 电力现货价格；
- 储能状态；
- 水库、防洪和生态约束。

这些因素相互耦合，单一预测模型或人工经验难以实现滚动优化。

### 2. 方案 A：多模型预测 + 优化器 + 调度 Agent

#### Agent 分工

- **气象/水文预测 Agent**：生成多时间尺度预测；
- **功率预测 Agent**：预测风电、光伏、水电出力；
- **市场分析 Agent**：分析价格、供需和交易规则；
- **调度优化 Agent**：在设备、水库、储能和市场约束下生成方案；
- **解释 Agent**：说明预测偏差、方案收益与风险。

#### 工作流

```text
气象/水文/设备/市场数据
        ↓
数据质量检查
        ↓
多模型预测与情景生成
        ↓
调度、交易、储能联合优化
        ↓
输出计划、报价草案和风险提示
        ↓
调度员/交易员审批
        ↓
执行与偏差复盘
```

#### 适合的 KPI

- 风光功率预测 MAPE；
- 来水预测误差；
- 电价预测误差；
- 弃风弃光率；
- 交易偏差考核；
- 调度计划可行率；
- 储能利用率；
- 综合利润或单位发电成本。

### 3. 方案 B：预测看板 + 市场规则助手

适合作为低风险先导：

- 提供功率、来水、电价预测；
- 自动检查市场规则；
- 生成交易和调度草案；
- 由交易员或调度员最终提交；
- 不允许自动报价和自动改变调度计划。

### 4. 已检索案例

国家能源局报道，“擎源”可用于气象预测、水情风险预警和市场形势分析：

- 新能源功率预测准确率提高 2.8%；
- 国能山西霍州电厂节点电价预测准确率较传统方式提高 6.2%；
- 600 MW 机组现货交易后，报道其生产成本下降 0.3%、盈利能力提升 2%。[S1]

上述指标为官方报道中的披露值，但尚未获得完整的基线、样本区间、统计方法和独立第三方验证，应在投资决策前复核。

## 场景 4：安全生产、环保合规与现场巡检

### 1. 典型应用

- 人员违章行为识别；
- 安全帽、工装、作业票和安全距离识别；
- 高风险区域入侵检测；
- 红外热像异常检测；
- 烟火、泄漏和环境异常识别；
- 环保排放数据分析；
- 危废管理与合规报告生成；
- 技术监督检查报告生成。

### 2. 推荐方案

```text
视频/图像/传感器/生产系统
        ↓
视觉模型与规则引擎
        ↓
风险事件识别
        ↓
多模态 Agent 解释事件并关联制度
        ↓
告警推送与分级处置
        ↓
人工确认、闭环和审计
```

视觉模型负责“看”，规则引擎负责“判定边界”，大模型负责：

- 解释告警；
- 关联规程；
- 生成整改建议；
- 生成安全报告；
- 形成审计记录。

不建议由大模型单独判定重大安全事故或替代安全管理人员。

### 3. 已检索案例

国家能源局报道，“擎源”安全环保域覆盖技术监督、班组安全和违章识别等场景：

- 技术监督检查评价效率提升 100% 以上；
- 违章识别从预判到告警推送约 15 秒；
- 视觉识别准确率披露为 85%。[S1]

人民网报道，中国大唐建设现场安全管控系统，用于识别人员违章、设备隐患和环境异常；报道称部分场景巡检工作量降低约 30%。[S2]

## 场景 5：现场运维与远程专家协同

### 1. 适用场景

尤其适合：

- 偏远水电站；
- 海上风电；
- 分散式光伏；
- 多场站集中运维；
- 专家资源不足的区域；
- 夜间或恶劣天气作业。

### 2. 方案

现场人员通过手机、工业平板、语音或 AR 设备访问 AI 现场助手：

- 拍摄设备铭牌、仪表和异常部件；
- 上传红外图像或声纹；
- 语音描述现场问题；
- 调取设备说明书和安全规程；
- 生成排查步骤；
- 自动记录现场处置过程；
- 必要时转接远程专家。

### 3. 技术架构

- 视觉模型：识别仪表、裂纹、渗漏、腐蚀、异物；
- 语音模型：支持嘈杂环境下语音交互；
- RAG：检索设备手册、操作票和安全规程；
- 工具调用：读取资产信息、历史工单和备件库存；
- 工作流：生成工单和升级专家；
- 人工审批：涉及停机、隔离、动火等操作时强制审批。

Oracle 展示过面向能源和水务现场人员的 GenAI Copilot 方案，组合使用 RAG、视觉和语音能力，接入设备文档、安全规程、IoT 数据和历史维护记录。但该资料属于活动议程/方案展示，不能据此认定已在具体发电企业生产部署。[S8]

# 三、发电行业 Agent 方案对比

| 方案 | 主要能力 | 数据要求 | 风险 | 适用阶段 |
|---|---|---:|---:|---|
| RAG 运维知识助手 | 规程问答、故障检索、报告生成 | 中 | 低 | 第一阶段 |
| 时序异常检测 + RAG | 预警、诊断、处置建议 | 高 | 中 | 第一/二阶段 |
| 多 Agent 运维闭环 | 诊断、工单、备件、排程 | 高 | 中高 | 第二阶段 |
| 预测模型 + 优化器 | 运行优化、交易和调度 | 高 | 高 | 第二/三阶段 |
| 数字孪生 + 受控 Agent | 仿真、策略验证、受控优化 | 很高 | 可控但复杂 | 第三阶段 |
| 端到端自动控制 Agent | 自动调参、自动执行 | 很高 | 很高 | 暂不建议直接采用 |

# 四、建议的落地路线

## 阶段 1：知识与只读 Copilot，约 2—3 个月

优先场景：

- 设备规程问答；
- 检修记录检索；
- 运行日志总结；
- 交接班报告；
- 安全规程问答；
- 告警解释。

必要条件：

- 统一文档版本；
- 权限分级；
- 设备编码统一；
- 强制返回来源引用；
- 建立问题集和人工评测集。

## 阶段 2：预测性维护和审批式 Agent，约 3—6 个月

优先场景：

- 锅炉、汽机、发电机、主变、风机齿轮箱等关键设备；
- 异常检测；
- 健康度评估；
- 故障根因分析；
- 检修工单草稿；
- 备件需求建议。

要求：

- EAM/CMMS 接口；
- 历史故障标签；
- 数据质量监控；
- 人工审批；
- 全量审计日志。

## 阶段 3：运行优化和多能协同，约 6—12 个月

优先场景：

- 风光功率预测；
- 水文预测；
- 电价预测；
- 储能调度；
- 燃烧优化；
- 厂用电优化；
- 水风光火储协同。

要求：

- 数字孪生或仿真环境；
- 安全约束和回滚机制；
- 预测回测；
- 极端天气和异常工况应急策略；
- 交易、调度和生产多部门审批。

# 五、重点治理要求

发电属于关键基础设施和高安全责任行业，建议至少落实以下控制：

1. **OT/IT 隔离**：AI 默认只读访问生产控制系统。
2. **最小权限**：不同 Agent 只访问必要的数据和 API。
3. **禁止直接控制**：大模型不能直接向 DCS、PLC 写入控制命令。
4. **来源可追溯**：回答必须引用规程、数据时间戳或历史案例。
5. **人工兜底**：停机、启机、隔离、动火、调度和报价必须人工确认。
6. **提示注入防护**：外部文档、日志和现场输入不能覆盖系统安全规则。
7. **模型漂移监测**：持续评估不同机组、煤质、季节和工况下的准确率。
8. **审计留痕**：记录输入、检���文档、模型输出、人工修改和最终动作。
9. **仿真先行**：任何闭环控制前，必须经过历史回放和仿真验证。
10. **故障降级**：AI 不可用时，系统应自动退回原有规则和人工流程。
